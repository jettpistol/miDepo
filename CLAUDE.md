## What this is

A warehouse tool for small book warehouses, first client **Ovnipress**. It is a **layer on top of Fierro** (an Argentine ERP for the book trade), not a replacement: Fierro owns catalogue, customers, orders, remitos and invoices; miDepo owns which shelf every copy is on and the scan-by-scan floor work. Why, and what was decided with the owner: [docs/DECISIONS.md](docs/DECISIONS.md). What is known about Fierro: [docs/fierro/README.md](docs/fierro/README.md).

**There is no real Fierro connection.** Everything runs against a simulated Fierro with invented data. Do not present anything as tested against real Fierro.

## Language rules

- **Everything a user sees is Spanish (Argentina, voseo):** screens, errors, the manual in `wiki/`. No English strings in the UI.
- Domain names in code are Spanish and match Fierro's vocabulary (`pedido`, `ubicación`, `devolución`). Keep them; do not translate identifiers.
- Docs, README and commit messages are English. Code comments are mostly Spanish; follow the file you are in.

## Rules that keep the data correct

1. **Stock quantities change in one place only:** `moverStock` in `src/lib/stock.ts`. It refuses negative stock and always writes a `movimientos` row. Never `update(stock)` anywhere else.
2. **Warehouse rules live in `src/lib/flujos/*.ts`** and take a `Ctx` (`db`, `empresaId`, `usuarioId`). They throw `ErrorUsuario` with a message meant to be shown as is. Screens and actions stay thin.
3. **Every query filters by `empresaId`.** Companies share one database. A missed filter leaks data between clients. `tests/flujos.test.ts` covers a few paths; there has been no systematic audit.
4. **Inside `db.transaction(async (tx) => …)` use only `tx`.** Calling `db` inside it deadlocks on the embedded database (this happened in `sincronizar`). Do reads that need `db` before opening the transaction.
5. **Server actions are built with `accion(rolMinimo, fn)`** (`src/lib/accion.ts`): it checks the session and role, turns `ErrorUsuario` into a message, and revalidates. `redirect()` works inside because `intentar` re-throws errors that carry a `digest`.
6. **Anything that leaves for Fierro goes through the `ConectorFierro` interface** (`src/lib/fierro/tipos.ts`). Do not call the simulator from elsewhere.
7. **Colours are tokens, never hex in components.** Use the Tailwind names from `src/app/globals.css` (`bg-acento`, `text-acento-texto`, `bg-superficie`, …). The accent is per user and set on `<html>` by the root layout.
8. **Scan forms use `<Escaneo>`** (`src/components/Escaneo.tsx`): it submits through `startTransition` so what was scanned survives an error, and it plays a sound. Do not replace it with a plain form action.

## Before you say it works

`npm run typecheck`, `npm test`, `npx next build`, and for any UI or flow change, the browser scripts. A green type-check is not evidence that a screen works. Say what you ran and what you did not (physical phones, camera, real Fierro, real hosting are all untested).
